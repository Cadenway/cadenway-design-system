Add two opt-in inputs to `cw-sidebar` for the application shell of the mockup (`App.dc.html`). `overlayBelow="lg"` (default `md`, the phone drawer only) also floats the expanded sidebar over the content between 768 and 1023 px, with a `shadow-md`: it starts hidden there instead of showing the icon rail, closes on Escape and on a click outside it (a transparent backdrop), stays open when an item is followed, and opens again when the window grows back to a desktop width. `backdrop="container"` (default `viewport`) makes the backdrop `absolute` inside the nearest positioned ancestor instead of `fixed` over the viewport, so it leaves out the bottom tab bar of `cw-app-rail`; use it with `overlayBelow="lg"` when controls sit beside the content panel. When a floating sidebar (the phone drawer or the tablet overlay) closes with the focus inside it, however it closes, the focus now goes back to the element that opened it, or to a visible toggle outside it, instead of staying in the inert navigation. The phone and tablet media queries now use Tailwind's rem breakpoints (`48rem`, `64rem`), so the script and the classes switch together whatever the default font size. New types `CwSidebarOverlayBelow` and `CwSidebarBackdrop`.
